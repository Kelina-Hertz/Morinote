# Morinote IDE

版本：`0.2.21`。面向 Windows，使用 Ren’Py 8.5.3。

这是仓库游戏的可视化编辑工具。IDE 源码独立放在 `creator/`，不参与游戏启动或发行；仍可直接通过 Ren’Py Launcher 运行根目录游戏。

## 使用免安装版

仓库包含 `portable/Morinote-IDE-0.2.21-no-ai.1-win-x64.zip`，通过 Git LFS 保存，内含 Electron、Python 和 Ren’Py 8.5.3。Windows x64 用户无需另装 Node.js、Python 或 Ren’Py，也无需构建源码。

1. 安装 Git LFS，在仓库根目录运行 `git lfs install`，然后运行 `git lfs pull` 下载免安装包及游戏素材。使用 GitHub Desktop 时，也应确认 LFS 文件已经完整下载。
2. 双击 [`启动IDE.cmd`](启动IDE.cmd)。首次启动校验压缩包并解压到 `.portable/`，可能需要等待；以后直接启动已解压版本。
3. 首次启动自动打开当前仓库的游戏，以后恢复上次工程；也可手动打开其他工程。

本机已有本地构建、Electron 开发依赖和 Ren’Py SDK 时，「启动IDE.cmd」优先运行 `dist/` 的当前构建及本地制作服务；其他环境继续启动免安装包。修改源码后需先构建前端再重开 IDE。

启动依赖 Windows 自带的 PowerShell 5.1，脚本仅为当前进程设置执行方式，不修改系统执行策略。若启动窗口提示下载的只是 LFS 指针，请先完成 `git lfs pull`。从 GitHub 网页下载的源码 ZIP 不保证包含 LFS 实体，推荐使用 Git + Git LFS 克隆。

解压缓存、构建目录和单独的开发 SDK 不进入 Git；**免安装 ZIP 和清单进入 Git**，不包含 Morinote 私有素材或 C2-1，游戏素材仍读取当前项目。

也可手动解压免安装 ZIP 后启动 `win-unpacked/Morinote IDE.exe`；要自动识别本仓库，请保持解压目录位于仓库内。若移到仓库外，启动后手动打开工程。

## 从源码构建

需要 Node.js 22 LTS、npm，以及 Windows 版 Ren’Py 8.5.3 SDK。

在 PowerShell 中：

```powershell
cd creator
npm ci
$env:CREATOR_RENPY_SDK = 'C:\Tools\renpy-8.5.3-sdk'
npm run build
npm start
```

`CREATOR_RENPY_SDK` 指向解压后的 SDK 根目录，其中应有 `renpy.py` 和 `lib/py3-windows-x86_64/python.exe`。也可将 SDK 解压到仓库根目录的 `renpy-8.5.3-sdk/`。

生成含运行依赖的免安装目录、仓库分发 ZIP 及校验清单：

```powershell
npm run package:dir
```

构建命令只编译打包，不自动启动游戏或运行测试。打包完成后同步更新 `portable/manifest.json`；仅重新压缩已构建目录可运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/package-portable.ps1`。发布新版本时一并提交版本配置、ZIP、清单和启动脚本，ZIP 使用 Git LFS 上传。

## 剧情图适配

首次打开现有 Morinote 时，直接从 RPY 建图并采用共享的场景名称预设，不依赖作者机器上的 `.creator` 缓存。用户自行改过的名称优先保留。默认展开第一章、按执行方向纵向排列，手机会话收进所属场景；末尾单一返回标题选项显示为一张收尾卡片，源码细节模式保留原步骤。

第一章主干为：噩梦醒后 → 百团巡游 → 摊位初遇 → 答题抽奖 → 与文竹同行 → 组织部宣讲 → 加入组织部。场景名称、摘要和分组仅是 IDE 展示配置，不更改剧情或原 label。总图不混入 OVA、系统功能或已识别的测试入口。

仓库存在带编号的同名脚本副本。默认剧情展示及配置编辑优先采用同目录下带编号的版本；多个编号按 Ren’Py 的文件名排序选择，同名标签之外的独有内容仍保留。提供「同名副本」入口查看所有相关源码；完整控制流索引仍保留重复声明和不明确的运行目标。此展示规则不删除副本，也不解决 Ren’Py 本身的重复标签问题；原生运行仍需用户另行验收。



## 功能

- 主线剧情总图、章节折叠、三轨编辑和多角色构图。
- 项目独立的虚拟素材库、临时替代、缺失占位和引用定位。
- 项目文件、Monaco 源码编辑、三方分块合并。
- 手动保存、关闭时提示未保存修改、历史恢复、多文件保存中断恢复。
- 手机、通讯录、OVA、成就和游戏配置的已识别字段编辑。
- 原游戏／片段试玩、独立 Ren’Py 预览窗口、参数联动和立绘动作预览。
- 拖动面板、收起／拉出和中央编辑区最小宽度。
- 打开 Ren’Py 原生启动器构建游戏发行版。


## 使用 Codex 导入 Word 剧本

仓库提供共享 Skill：[morinote-word-import](../.agents/skills/morinote-word-import/SKILL.md)。在 Codex 中打开本仓库，提供 `.docx` 路径后可以直接说：

> 使用 $morinote-word-import 载入这个 Word 剧本，作为第二章的独立导入稿。保留原文、选项和手机聊天；缺失素材用占位，有合适差分则临时替代并保留缺失提示。更新 IDE 中的场景名称和分组，暂不接入主线，不运行测试或试玩。

Skill 在 `.agents/skills/` 中随仓库共享，不需要安装模型 SDK。若当前 Codex 客户端未自动列出它，可以直接让 Codex 读取上述 `SKILL.md`。

导入过程为：

1. 保留原 Word，提取正文、表格位置、段落编号及附注信息。
2. Codex 区分对白、旁白、手机消息、分支、演出和制作备注。
3. 生成独立原生 RPY，复用现有人物及演出系统，登记缺失或临时替代素材。
4. 保存段落到文字节点、label 和源码行的对应关系，刷新 IDE 名称与总图分组。
5. 在 IDE 查看三轨和缺口；需要时再由用户发起试玩、正文确认或主线接入。

原稿与导入记录默认放在 `.creator/imports/<章节>/<版本>/`，不会自动提交 Git；新剧情源码位于 `game/creator_imports/<章节>/`，素材运行配置位于 `game/creator_assets/`。再次更新时沿用已有 label 和人工演出，不整章覆盖用户修改。

辅助脚本只负责提取、来源登记核对和索引刷新，不能单独理解剧情，也不是“一键把任意 Word 转成正确游戏”的转换器。由外部 Codex 执行 Skill，不改变此 IDE 的无 AI 版本定位。

## 游戏文件与保存

### 场景、选项与片段测试

- 通过画布出口的「＋」创建后续剧情、选项分支或条件判断，也可连接已有剧情或明确设为「结束此段」。新剧情保留原后续，独立新建不会改写原剧情。
- 可编辑出口显示连接点，也可拖动已有连线的目标端；普通拖线直接加入编辑稿，形成循环时先提示确认。选中连线按 Delete 或 Backspace 可断开，原出口显示「待连接」。复杂控制流、重复标签和带参数目标保留高级区内的源码入口，不自动改写。
- 「未接入主线」按静态连接判断；无法确定的连接状态在节点高级区说明。通过「视图」可筛选未接入的剧情；这些状态不限制独立片段测试。

- 在剧情总图新增场景时，默认只需填写场景名称。IDE 自动生成唯一标签，默认写入 `game/creator_scenes.rpy`；标签和文件路径可在「高级设置」中调整。新场景先独立创建，不改变现有剧情连接。
- 内容编辑中的新增选项可逐行填写文字并搜索目标场景；总图中的选项分支直接在画布创建并拖线。两处都可添加、删除、调整顺序；JSON 保留在「高级设置」，格式有误时需修正或明确放弃修改后才能提交。
- 片段测试默认只选起始场景；参数、状态和前置标签调用收进「高级设置」。已有配置继续生效，界面会提示「已使用高级配置」。
- 新场景的名称和章节作为相邻注释保存在源码中；自定义展示名称和章节配置优先。创建操作先进入编辑稿，支持撤销、重做和草稿恢复，保存后才写入游戏文件。

### 像流程图一样创作

- 右键或双击画布空白处，选择「剧情块」「选项分支」或「条件判断」；顶部「新建」和出口「＋」使用同一个创建菜单。
- 三类节点都在画布卡片内填写，Enter 创建、Esc 取消；标签、文件位置和选项 JSON 收入「高级设置」。新建节点避开已有节点，创建完成后定位到新节点；Alt+↓／Alt+→ 可连续创建后续剧情块。
- 从出口拖到已有节点即可连接；拖到空白处可新建后续并自动接入。新剧情块保留原后续；新分支的第一项、新判断的「是」出口保留原后续，其余出口显示「待连接」。新独立节点默认待连接，其原生源码仍以安全的 return 结束；旧剧本的 return 继续显示「结束此段」。
- 新建分支只需填写选项文字，不要求先选择目标。创建后从各选项出口拖线；选项文字可直接在节点上改，「＋ 选项」添加一个待连接出口。
- 条件判断直接选择已有全局状态、比较方式和值，名称自动生成为「score ≥ 3」等易读条件，不必另起名称。双击判断可修改条件；复杂表达式放在高级设置中。
- 总图默认显示剧情名称、内容摘要、选项和出口状态；双击剧情块进入内容编辑，双击选项块聚焦文字。右侧节点信息默认收起，标签、文件位置、调用信息集中在高级区；「视图 → 源码结构」保留原生语句。
- 章节展开、折叠时都显示章节入口和「连接下一章」；可以选择下一章，也可将章节出口拖到下一章顶部的入口圆点。跨章连线显示为章节之间的连接，内部仍使用真实的静态跳转。
- 本章入口优先沿用已有外部连接，否则选择默认起点；「入口设置」可指定后续新连接使用的入口。存在多个出口时可指定接哪条后续；已有跳转不会因更改默认入口而悄悄改向。设置与连线都需手动保存，可撤销、重做。
- 结尾的简单选项可单独连接下一章，即使前文有自定义函数调用；不会改写前文、调用或选项文字。重复标签、复杂分支体和动态出口仍保留保护。
- 所有创建和连接变化先进入编辑稿，支持撤销、重做；手动保存后才影响游戏文件。
- 拖线时高亮可连接的节点，可在整个目标块内松手；非法目标会说明原因。把独立且具有简单出口的剧情块拖入连线，会显示「松开插入」预览，并同时保留原后续。
- Shift 框选或 Ctrl 多选后可「整理所选」，也可按章节或全图「整理布局」，支持横向、纵向；整理和节点移动可以撤销、重做。整理采用节点实际尺寸，不修改剧情连接。
- 本轮交互参考 [draw.io 的连接方式](https://www.drawio.com/docs/manual/connectors/) 与 [Whimsical 的快速添加及自动布局](https://whimsical.com/learn/get-started/flowcharts)。

本组画布操作的定向界面检查使用独立临时工程，不启动游戏或保存正式剧情：构建后可运行 `node_modules/.bin/electron.cmd electron/tests/run-canvas-ui.cjs`，结果位于 `.checks/canvas-ui/`。

章节入口与跨章连接的定向检查为 `node_modules/.bin/electron.cmd electron/tests/run-chapter-ui.cjs`，覆盖展开／折叠入口、默认入口、指定入口、章节拖线、撤销重做及仅修改编辑稿。

性能定向检查可运行 `node_modules/.bin/electron.cmd electron/tests/run-flow-performance.cjs --verify`：确认一次可视化修改只分析一次源码，纯布局操作不分析源码，且不保存剧情文件。工程文件按来源索引分类并复用结果；空闲状态轮询不触发重复界面刷新，拖动插入检测先筛除远处连线。

关闭窗口时不再重建文件列表和总图；「不保存」只清理放弃的恢复记录，「保存」保留源码冲突检查、事务保存和 Ren’Py 校验。关闭期间暂停后台分析和状态刷新；取消关闭或保存失败后可继续编辑。关闭定向检查可运行 `node_modules/.bin/electron.cmd electron/tests/run-save-ui.cjs --verify`，以及同一命令增加 `--discard-close` 检查不保存退出。

打开工程只建立索引和项目内 `.creator/editor/` 元数据，不重构原游戏。修改先进入编辑器；点击「保存全部」或按 `Ctrl+S` 才保存源码、布局和项目配置；不再定时备份编辑稿或在试玩前自动保存。关闭窗口或切换项目时，有未保存修改会提示「保存／不保存／取消」；保存失败不会退出，选择不保存后不会在下次打开时恢复已放弃的编辑稿。需要当前编辑稿的测试或检查会提示先手动保存，原游戏试玩仍可使用磁盘版本。

更改素材名称、分类和对应关系不移动或覆盖实际素材；首次保存素材库修改会创建 `game/creator_assets/asset_bindings.rpy`，供原生运行和打包读取。

`.creator/` 包含本地索引、草稿和恢复记录，不提交 Git。不要把它当成唯一的游戏版本备份。游戏发行使用 Ren’Py Launcher 的「构建发行版」，无需包含 IDE。

## 当前范围

以 Morinote 为适配工程；复杂 ATL、自定义显示对象和动态表达式保留源码入口，不保证完整可视化解析。热更新可能从场景测试入口重启。

本次交付进行了静态复核和编译打包；按项目约定，未运行自动测试、故障注入或游戏试玩。保存恢复、素材替代和原生发行效果仍需后续专项验收。

共享 Skill 及其 Word 辅助脚本进行了源码编写和语法检查，未在本次任务中实际导入 Word 或运行生成章节。

同名剧本的总图、静态连线和可视化编辑统一默认采用编号版本（例如 `script_c1a (1).rpy`），无需重复选择；按 Ren’Py 文件名顺序选定编号副本，保留其他版本。不同剧本之间或同一文件内的同名标签仍视为冲突；动态出口等安全限制继续生效。连接先进入编辑稿，手动保存后才写入所采用的源码文件。
