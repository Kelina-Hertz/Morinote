# 对话式媒体创作验收记录 · 2026-11-01

本轮在 Creator 0.4.3 源码上实现对话式创作、配音导演、候选版本和用户验收。测试使用独立工程，没有发起新的真实文字模型、Seedream 或 MiniMax 收费调用。自动化点击验收仅验证软件链路，不代表用户认可素材的艺术质量。

## 已实现

- 图片、单句配音和片段可以先保存创作要求、提示词及参数。明确要求生成后才产出候选；同一用户消息不能自行反复修订同一项并收费。
- 导演说明、原台词与实际合成文本分开。支持声线、语速、情绪、音量、音高、停顿、读音及语气标记，保留尚未落实的要求。导演说明不进入朗读正文。
- 根据 [MiniMax 官方接口](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)，修正中性情绪为 calm，旧 neutral 转为 calm；speech-2.8 不支持 fluent/whisper，在提交前拒绝。保存实际服务参数，避免将导演说明误当成已经传递的控制项。
- 创作项、提示词版本、候选、反馈与验收相互关联。支持逐项生成、版本对比、选旧版本、图片参考编辑，以及按钮或明确聊天验收。指向不明确时询问，不由模型代验。
- 候选保存于项目 `.creator/media/`。临时试玩只在受控执行快照安装媒体，验收前不提交正式源码或映射。验收后复用统一源码事务，支持撤销、Hot Exit、冲突合并及应用中断恢复。
- 预算跨轮累计；重复点击复用请求，明确要求新版本才建立收费尝试。结果未知不自动重发。候选就绪通知不依赖最终模型总结；旧记录不补造用户验收。
- 新候选及迟到的检查回执不能把旧版本检查标为新稿通过。指南仍按需读取；生成返回精简摘要，完整提示词需要时再查询。

## 验证结果

| 验证 | 结果 |
|---|---|
| 默认 npm test | 51 项 Node、11 项前端逻辑、183 项 Python，共 245 项通过；含类型检查 |
| 界面构建 | 通过，既有 Monaco 大分块提示仍存在 |
| 普通创作界面与 DSH 工具 | 模拟文字请求 2 次，模拟媒体 3 次（图片 1、配音 2），真实模型和媒体 API 请求 0 次 |
| 低额度模式 | 模拟文字请求 2 次，模拟媒体 2 次；累计计量、候选试玩及聊天验收通过，真实 API 请求 0 次 |
| Ren’Py 8.5.3 | 候选 lint、隔离真实窗口、两条选项路线、Voice 正在播放断言及返回标题均通过 |
| Skill | frontmatter 与 6 个本地文档链接检查通过 |

普通界面验收覆盖：正常聊天生成候选 → 查看图片和音频 → 验收前 lint、临时试玩 → 自然语言验收并应用 → 打开三轨 → 修改导演说明和语速，仅重做配音 → 保留已验收背景及当前游戏 → 选回旧配音 → 在三轨手工修改旁白 → 验收时发现冲突 → 使用现有合并界面保留手工修改并保存。选旧版本、合并和应用没有增加生成调用。

第一次复查发现低额度模式工具上下文过大，已改为只加载验收所需工具，并压缩生成返回。测试启动器的后台输出管道曾产生 EPIPE 弹窗；最终复查保留独立日志输出通道后完整通过。并发索引中的预期过期请求被拒绝，随后使用保存后的有效索引，没有覆盖手工内容。

默认测试读取现有 Morinote 源码时仍有既有 `invalid escape sequence` 提示，新增测试无失败。未进行新的真实 API 或主观配音表演验收，未重新打包。
