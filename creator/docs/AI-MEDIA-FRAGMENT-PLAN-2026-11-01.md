## 1. 用户目标与已确定的范围

用户先用 IDE 制作自己的 Galgame，再逐步提炼通用开源框架。首版优先使用云 API，减少部署维护。用户已经提供 Seedream 与 MiniMax 凭据，但本计划不包含密钥，也不将密钥存入仓库。执行任务应通过本机凭据配置使用它们。

本阶段最终交付：用户在已有 AI 侧栏输入简单自然语言，系统理解要求、安排剧情和演出、按需生成图片和配音，将结果放入真实素材库并绑定到原生 RPY；用户可以编辑、保存、试玩并再次打开该片段。

| 能力 | 本阶段范围 |
|---|---|
| 剧情理解、台词和分支规划 | 复用当前 IDE 已配置的文本 AI / DSH 链路，不新增文本模型供应商 |
| 图片生成 | 实接 Seedream；支持一张背景、CG 或普通图像及参考图编辑的基础请求 |
| 配音生成 | 实接 MiniMax TTS；固定系统声线、逐句生成、绑定 Voice |
| 音乐生成 | 只提供类型、能力注册和“待开发”状态；零真实调用 |
| 独立音效生成 | 同上；MiniMax 台词内笑声等不等于独立音效生成 |
| 视频 / AI 过场生成 | 同上；即使 Ark Key 可访问 Seedance，也不接入、不调用 |
| 其他图片或配音供应商 | 只预留扩展边界；不实现 Gemini、GPT Image、ElevenLabs 等客户端 |

“目前只用两个”指本次新增媒体服务。Seedream 与 TTS 不承担剧情理解：若原有文本 AI 尚未配置，明确显示该依赖，不能用模板冒充已完成自然语言理解。现有文本 AI 的调用也须计入验收用量。

首版支持的片段：一个主要场景、1–2 个角色、约 6–12 句文本、一组二选一分支及两个可达结果。普通文本、旁白、背景、已有立绘、淡入淡出、单句配音必须能组合。较复杂结构继续使用已有编辑能力，不将本轮验收扩大为任意玩法生成。

不要求本阶段实现：训练模型、克隆音色、自动精细抠图、Live2D 拆件与绑定、多人 CG 的绝对一致性、复杂长过场、云账户收费系统或公开托管服务。已有 BGM / 音效可以引用，但不得冒充 AI 新生成。

## 2. 最终用户体验与验收输入

一次性配置媒体服务和已有文本 AI 后，用户无需填写 JSON、API 参数、素材路径或 RPY 代码。继续使用现有 AI 侧栏，任务卡显示实际阶段、消耗计数和入口。

真实验收只发送一次下面的自然语言需求：

> 做一个一分钟左右的雨夜校园片段。我在校门口遇见忘带伞的同学，可以选择送她回家或把伞借给她，最后都有各自的回应。新画一张雨夜校门背景，只给她第一句台词配音，其他素材优先用已有的，没有合适立绘就只显示背景和对话。

预期结果：

- 生成约 6–10 句可阅读文本；阅读时长是创作目标，不做固定一分钟的计时承诺。
- 有一组二选一选项，两条路线均有回应，均能正确结束或汇合。
- 一张真实 Seedream 背景在游戏里可见；一条真实 MiniMax 短配音与正确台词对应。
- 该句配音文本不超过 30 个汉字；包括标点、标签后的计费字符不超过 100。
- 其余台词不配音是需求中的有意安排。缺少合适立绘时使用背景加对话的正常演出，不悄悄换成无关角色或伪造占位素材。
- RPY、三轨、流程图、素材库和实际试玩反映同一个版本。
- 用户能继续改一句台词、保存、重开工程；修改不触发自动付费重生成。
- 保留既有源码审阅 / checkpoint / 试玩交互。除已有必要确认或点击试玩外，不要求用户补写技术指令，不额外增加逐素材批准弹窗。

“提供生成按钮”或“API 返回成功”都不算完成。必须从这段自然语言一直走到真实 Ren'Py 片段。

## 4. 建议的实现结构

主链路：

```text
简单自然语言 + 少量相关项目上下文
    → 现有文本 AI 生成片段计划
    → 本地结构、素材与额度校验
    → 复用已有素材 / 提交受限媒体任务
    → 产物校验与受管入库
    → 原生 RPY 与素材映射事务
    → 重新索引、绑定画面与单句 Voice
    → 真实引擎检查、试玩、继续编辑
```

### 4.1 分层和文件建议

以下为建议的新文件名称，执行者可依代码组织调整，不必逐字照搬：

- `electron/media/providers/seedream.cjs`、`minimax.cjs`：HTTP 适配与响应归一化，支持注入假 transport。
- `electron/media/provider-registry.cjs`：能力目录、可用性和待开发能力。
- `electron/media/media-store.cjs`：媒体配置及加密凭据，复用 `SecureStore` 的机制。
- `electron/media/job-manager.cjs`：持久任务、缓存、额度预占、重启恢复、取消和调用台账。
- `electron/media/fragment-coordinator.cjs`：校验计划后按确定步骤协调生成、入库和绑定，避免每个步骤再次问模型。
- `backend/generated_media.py`：限定目录内的产物验证、登记和扫描挂接；不直接承担云凭据处理。
- `backend/fragment_authoring.py`：将受校验计划转换为原生源码编辑，沿用现有事务基础。
- `src/media-types.ts`、设置与任务卡组件：展示状态、预算、结果和编辑入口。

媒体网络调用由 Electron 主进程侧的受管服务发起，renderer 不直接持有调用凭据。任务执行方式应避免长请求阻塞界面。

### 4.2 统一接口，允许能力差异

最小抽象建议：

```typescript
type MediaKind = 'image' | 'voice' | 'music' | 'sfx' | 'video';
type Availability = 'ready' | 'unconfigured' | 'disabled' | 'planned';

interface ProviderDescriptor {
  id: string;
  kinds: MediaKind[];
  availability: Availability;
  capabilities: string[];
}

// 这是协议草图，不要求所有远端 API 都有异步任务、查询或取消接口。
interface MediaProvider {
  describe(): ProviderDescriptor;
  estimate(request: MediaRequest): CostEstimate;
  generate(request: MediaRequest, context: ProviderContext): Promise<MediaResult>;
}
```

`MediaRequest` 只带创作参数、模型、参考资源 ID / 摘要等，不带密钥。`ProviderContext` 内部解析凭据和预算，不能进入工具参数、LLM 上下文或 renderer 返回值。

`MediaResult` 至少包含：产物种类、实际 MIME、文件或数据、尺寸 / 时长、供应商请求 ID（如有）、usage（如有）、模型标识。原始响应不能直接写入日志或全部返回模型。

音乐、音效、视频只注册 `planned` 能力，调用返回稳定的 `CAPABILITY_NOT_IMPLEMENTED`；UI 显示“待开发”，不伪装 ready，不自动切换其他供应商。用户要求这些内容时，保留已经可完成的片段并说明缺项，可引用用户已有素材。

### 4.3 自然语言规划与源码

- 将当前选区、相关场景摘要、角色资料和少量匹配素材提供给已有文本 AI；不读取整部作品和完整媒体目录作为默认上下文。
- 规划结果是带版本的中间数据，包含角色、台词、旁白、分支、画面安排、配音目标和媒体需求；使用稳定的计划节点 ID，验证后再映射到实际 RPY 节点。
- 中间计划 JSON 只用于校验、任务恢复与溯源，不成为第二套可独立编辑的剧情权威源。
- 本地验证 ID 唯一性、角色 / 素材引用、分支目标、可达结束、句数和媒体数量。转义台词中的引号、换行及 Ren'Py 特殊语法；自然语言文本不能直接变成任意 Python / shell 执行。
- 通过当前 live 工具目录增加聚合生成工具，例如 `generate_fragment`。文本 AI 交付受约束的计划，后续生成、落盘、扫描和绑定由 coordinator 完成，减少逐步工具往返与 LLM 消耗。
- 同步更新当前工具说明：原有素材仍只读，只有已登记生成任务能向专用生成目录受管写入，避免旧描述让模型误判新能力不可用；不扩大为任意媒体写权限。
- 如果增加单项图片 / 配音工具，它们必须复用同一个 job manager 和额度台账，不能绕过限制。
- 新片段写入独立且不重名的 RPY 文件 / label；当前工程主线保持原样。验收工程可将其设为自己的入口。
- 原生索引的 nodeId 并非所有改动后都永久不变。提交 RPY 后重新解析，记录计划节点与实际节点映射；配音绑定同时检查文本摘要、说话人和目标版本。发现不一致时保留产物但不套用到旧行号。
- 异步结果到达时，若用户切换项目或编辑了目标内容，进入“产物已生成，待重新绑定 / 冲突处理”，不覆盖新稿。

## 5. 两个真实服务的接入要求

### 5.1 Seedream

- 供应商：火山方舟 Ark。
- 官方入口：`POST https://ark.cn-beijing.volces.com/api/v3/images/generations`。
- 当前候选模型：`doubao-seedream-5-0-pro-260628`；模型 ID / 已开通的推理接入点可配置，不能因不可用而偷偷改用其他付费模型。
- 第一阶段实现单图生成及可选参考图；正确处理 `url` / `b64_json` 等已启用的响应类型、HTTP 错误及响应体中的业务错误。
- 验收固定只请求一张背景，`size` 使用显式 `2048x1152`；关闭流式，不传组图、图层拆分等参数。该尺寸满足本次核对的 Pro 像素规则。执行时先根据官方文档验证参数，不能通过连续收费试错探测。
- 普通使用可调整画面说明、尺寸与参考图。透明立绘和自动抠图不作为本轮闭环的前置依赖；不要将“纯色背景”标成“透明 PNG”。
- 远端链接返回后及时保存实际文件，游戏运行不依赖临时 URL。

接口与参数以[官方图片生成文档](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh&redirect=1)为准。不要为 5.0 Pro 套用其它型号的组图、尺寸或流式参数。

### 5.2 MiniMax

- 使用与用户账户一致的官方区域配置；本计划默认中国站。
- 官方入口：`POST https://api.minimax.cn/v1/t2a_v2`。
- 默认模型：`speech-2.8-hd`；Turbo 可作为后续配置选项，本次验收不重复调用两个型号比较。
- 配置一个已存在、可用的中文系统 `voice_id`。从官方声线列表 / 已有配置选择，不编造 ID，不调用声线设计或克隆接口。
- 验收采用非流式、一个短句、一个音频文件；MP3 或经运行时验证可播放的格式即可，不新增不必要的外部转码依赖。
- 同时检查 HTTP 状态、`base_resp.status_code` 和音频内容；成功 HTTP 不等于合成成功。按实际响应正确解码十六进制音频或处理选定的返回格式，不保存 JSON 为音频文件。
- 第一阶段支持 voice_id、语速和官方支持的情绪 / 停顿 / 读音设置。将演出参数与玩家可见台词分开存储；音频标签不得出现在对白文本里。
- 配音完成后使用现有 `native_voice` / stage adapter 绑定，保存台词文本摘要。修改台词后标记配音过期，只有用户要求重新配音时才提交新任务。

字段和响应格式以[官方同步语音文档](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)为准；不依据 Key 外观猜测账户地区，不向多个域名轮流试发凭据。

## 6. 素材入库、事务、缓存与恢复

### 6.1 新增受管导入入口

1. 为项目内的生成产物增加独立路径，例如 `game/images/creator_generated/<jobId>/` 与 `game/audio/creator_generated/<jobId>/`。
2. 输入必须来自已登记任务的输出；服务端自行计算最终路径，不接受模型给出的任意绝对路径或 `..`。
3. 网络输出先进入私有暂存目录。校验文件头、MIME、可解码性、长度 / 大小与像素上限；下载不向返回的媒体 URL 携带云 API Authorization，拒绝越界路径与不合规重定向。
4. 使用不覆盖旧素材的原子落盘方式，再走实际资源扫描，将产物登记为真实资源。
5. 经既有源码事务创建 / 绑定虚拟素材，将其用于背景或指定台词 Voice。最终 RPY 只引用本地资源。
6. 若后续绑定失败，保留已经付费生成的文件，记录“已生成但未绑定”；修复绑定不得再次调用生成 API。

不能将现有源码事务等同于完整的二进制事务。需要记录任务、产物和源码批次的关系；撤销先撤销源码引用和映射，暂时保留可复用产物，不删除被其他场景引用的文件。自动清理和大规模垃圾回收不属于本阶段。

### 6.2 缓存与调用台账

缓存键覆盖：项目 / 账户命名空间、provider、模型、规范化创作参数、参考文件内容哈希，以及语音文本、声线和演出参数。不得仅以文件名、提示词或行号作为缓存键，也不得包含明文 Key。

提交前持久化任务并原子预占调用次数；多个对话、重复点击和应用重启共享同一验收台账。收费请求成功、失败或超时都保留提交记录。任务完成后关联实际文件哈希，复跑默认命中缓存。

不要假设远端支持幂等或请求查询。请求超时、断连或进程在提交后退出时，状态是“结果未知”，不得直接重发。只有供应商确有查询接口和有效 ID 时才查询原任务；否则保留记录并停止自动动作。

区分可重试操作：本地扫描 / 绑定、已取得链接的有限下载重试可以恢复；新的生成提交是另一次可能收费的动作。两家适配器与底层 SDK 均关闭自动收费重试。

### 6.3 状态与取消

建议状态：`planned → queued → submitted → output_ready → imported → bound`，以及 `failed / cancelled / uncertain / needs_rebind`。

“成功”至少区分生成成功、入库成功和片段可试玩，不能只有一个笼统绿色标记。取消会阻止排队任务与后续绑定；已提交的远端请求可能继续计费，只有供应商明确支持时才显示“远端已取消”。晚到产物可保存为未绑定结果，不改动当前工程。

- 脱敏 HTTP 日志、错误和请求摘要；不记录 Authorization、完整响应音频或未筛选的供应商对象。
- 保存设置只做本地格式校验，显示“已配置，未实测”。不通过自动生图或 TTS 来测试连接。最后的一次真实验收同时验证凭据和生成能力。
- 若执行任务无法访问原对话或本机尚未保存凭据，先完成零额度实现与测试，再通过本机设置录入；不得搜索聊天日志或把文档当作秘密传输渠道。真实验收缺凭据时明确写未执行。
- 如使用开发环境变量，只约定名称 `ARK_API_KEY`、`MINIMAX_API_KEY`，不填写真实值，不输出变量内容。账户区域与模型仍需显式配置。

## 8. 低额度验收的硬限制

开发默认 `mock` 模式，不访问真实生成端点。真实调用放在离线测试、参数检查和 UI 准备完成后的最后阶段。

| 类别 | 单次完整验收的默认限制 | 计量方式 |
|---|---|---|
| Seedream | 最多 1 次收费生成提交、1 张背景、0 张参考图、0 个变体 | 提交尝试计数，失败 / 超时也占名额 |
| MiniMax | 最多 1 次收费 TTS 提交，1 句 ≤30 汉字且 ≤100 计费字符 | 不设计、不克隆、不试听额外候选 |
| 已有文本 AI | 目标 1 次规划；硬上限 3 次实际模型请求，总输出上限建议 6,000 tokens | 包括 DSH 往返、总结、修补和额外审核，不按“用户只发了一条消息”计一次 |
| 音乐 / 音效 / 视频 / 其它 provider | 0 次 | 模拟调用也必须表现为未实现 |
| 收费生成自动重试 | 0 次 | 同时禁用 SDK 内部重试 |
| 重启、恢复、重开、试玩、再次 lint | 0 次生成调用 | 复用已有产物与本地工程 |

文本 AI 的 3 次上限是兼容现有工具往返的上限，不是要求用满。优先一次返回完整可校验计划，后续由 coordinator 执行；不为每张图、每句配音再调用 LLM。若当前 SDK 隐藏了调用次数，先加计量与限制再进行真实验收，不可只报告顶层会话数。

真实验收使用新建独立会话和精简上下文，不携带已有长聊天历史。输入预算建议每次估计不超过 8,000 tokens、整个验收累计估计不超过 16,000 tokens；包括 system、工具 schema、项目上下文与工具返回。没有可靠 tokenizer / 预计数接口时，把它明确记录为估算并限制上下文体积，不能宣称精确金额封顶。

6,000 输出 tokens 是整个验收的总量。每次提交前按剩余额度设置该文本 provider 实际支持的输出上限字段，并预占可用预算；不得三次分别设置 6,000 后才事后累计。usage 中可取得的推理 / thinking 等计费 tokens 也纳入记录，不以可见文本长度代替计费用量。调用结果未知时，不自动释放预占量或继续追加模型请求。

可将本次配置保存为独立 `acceptance-low-cost` profile：

```json
{
  "mode": "mock",
  "maxImageSubmissions": 1,
  "maxImageOutputs": 1,
  "maxVoiceSubmissions": 1,
  "maxVoiceBillableCharacters": 100,
  "maxLlmRequests": 3,
  "maxLlmInputTokensEstimatedPerRequest": 8000,
  "maxLlmInputTokensEstimatedTotal": 16000,
  "maxLlmOutputTokensTotal": 6000,
  "maxOtherMediaSubmissions": 0,
  "paidSubmissionRetries": 0,
  "estimatedMediaBudgetCny": 0.50
}
```

按本次核对的中国站标准价，指定 Seedream 低像素档背景约 ¥0.30；MiniMax HD 100 个计费字符上限约 ¥0.035，合计约 ¥0.335。`¥0.50` 是本地按已核实价格预占的媒体估算上限，不是供应商账单的强制封顶；不含已有文本 LLM、充值门槛或税费。价格和模型参数在执行前用官方文档核对，未知价格不得按零处理。依据：[Ark 定价](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)、[MiniMax 定价与汉字计数](https://platform.minimax.cn/docs/pricing/overview)。

额度必须按一个验收 runId 持久化，重启、换测试脚本、切对话或重新运行不能自动重置。首次真实生成失败时不自动追加额度；保留错误、已生成产物与未完成项。需要额外收费验证时先说明理由、已有消耗和新增上限，不能自行循环重试。

这里限制的是验收消耗。正常创作的图片数、配音数和预算由任务设置决定，不把“一张图一句配音”写死为生产功能上限。正常创作同样要在本地约束预算；用户已授权的任务预算内连续执行，不为每一步重复询问。

## 9. 分阶段实施任务

### P0：确认基线与隔离验收环境

- 重新检查适用 AGENTS、当前版本、测试入口和 Git 工作区，记录已有改动。
- 确认现有文本 AI 配置接口与 Ren'Py SDK 定位方式；不读取或输出密钥正文。
- 使用 `create_native_project()` 建立独立测试工程；可位于已忽略的 `.ui-test/media-fragment/` 下，源码中不硬编码绝对路径。
- 定义上述 plan / request / result / job 类型和验收 profile。

完成标准：在没有云凭据时，也能执行本地开发和所有 mock 测试。

### P1：媒体服务与任务基础

- 实现两个真实 provider 的参数构造、响应解码和错误归一化；同步完成模拟 transport。
- 实现媒体独立配置和加密存储、任务落盘、预算预占、缓存、取消与未知状态。
- 注册其它能力为 `planned`。默认测试启动不能自动检测余额、生成预览或试跑远端模型。

完成标准：契约和故障注入测试通过；没有真实 API 消耗。

### P2：受管产物入库与现有编辑能力连接

- 新增生成产物导入入口和限定目录，不扩大原有任意媒体写权限。
- 跑通暂存、验证、原子落盘、扫描、虚拟绑定、单句 Voice。
- 将源码批次与产物任务关联；补充失败恢复、撤销与版本冲突处理。

完成标准：用明确标记为 fixture 的本地图片 / 音频，从任务入口到真实 Ren'Py 预览通过。

### P3：自然语言生成片段

- 在当前 AI 工具目录 / 插件链路接入聚合生成工具和 compact context。
- 验证中间计划，生成原生 RPY，处理一组分支，按需求调度受限媒体。
- UI 增加进度卡、产物预览、打开片段和试玩入口；错误包含可恢复动作。
- 支持生成后继续手工编辑，内容修改只标记相关配音过期，不自动再次收费。

完成标准：使用固定 LLM fixture 从同一自然语言输入贯通所有本地步骤；并明确仍未证明真实模型理解能力。

### P4：离线回归与故障测试

- 完成下一节矩阵，检查新测试确实被默认测试入口执行。
- 检查构建产物中没有测试凭据、临时响应、真实音视频或验收工程。
- 不为本功能顺手升级 DSH / Electron / 文本模型，不进行全项目重构或修改正式游戏剧情。

完成标准：所有必需本地检查通过，真实生成提交计数仍为零。

### P5：一次受限真实验收与成果归档

- 使用真实配置和同一自然语言需求，从 IDE 正常入口执行一次。
- 计数器控制最多一张真实背景、一句真实配音，以及上限内的现有文本 AI 请求。
- 保留现有 checkpoint。不要绕过应用的确认逻辑，也不额外开启付费审核模型；如当前配置会产生审核调用，应计入 LLM 上限并如实记录。
- 真实产物入库后，检查 / 试玩两条路线，再离线复跑。无需为另一条分支再次生成素材。
- 记录实际用量、预计费用、真实窗口 / 画面 / 音频证据和未验证项。

完成标准：自然语言理解、真实两个供应商、素材绑定和真实引擎均有证据；无法完成的环节明确保留为未验收，不能由 mock 结果代替。

## 10. 验收矩阵与命令

| 项目 | 模式 / 额度 | 必须验证 |
|---|---|---|
| Seedream 参数 / 解码 | mock / 0 | 单图参数合法；URL / Base64 路径；无效图片拒绝入库；错误不会标成功 |
| MiniMax 参数 / 解码 | mock / 0 | 业务状态码、十六进制音频解码、空音频、计费字符限制、声线配置 |
| 凭据隔离 | mock / 0 | 设置读取只含状态；Key 不出现在工具参数、日志、错误、工程和导出内容 |
| 未开发能力 | mock / 0 | 音乐 / SFX / 视频不可提交；显示待开发；无隐式供应商回退 |
| 计划校验 | fixture LLM / 0 | 错误引用、重复 ID、超额需求、不完整分支在提交前被阻止 |
| 双分支运行 | fixture 产物 / 0 | 两条路线可达，画面和文本正确，单句 Voice 对应正确 |
| 并发与缓存 | mock / 0 | 相同请求 / 重复点击 / 重启不会重复提交；输入摘要变化后缓存不误命中 |
| 文本 AI 用量控制 | mock / 0 | 独立会话不带长历史；工具 / 上下文纳入输入估计；每次输出上限受总剩余额度约束；隐藏 SDK 重试不会绕过计数 |
| 超时 / 429 / 服务失败 | 注入故障 / 0 | 提交次数准确，停止自动重发，保留已生成内容与可编辑草稿 |
| 取消与项目切换 | mock / 0 | 阻止后续收费提交；晚到结果不覆盖新项目或新稿 |
| 落盘 / 绑定失败与恢复 | mock / 0 | 已生成文件可继续绑定；不为恢复再付费；不破坏共享资源 |
| 保存、重开、撤销 | 本地 / 0 | RPY 与素材一致；恢复不发云请求；其他场景共享媒体不被删除 |
| 真实自然语言端到端 | live / 受第 8 节限制 | 一次自然语言输入生成真实图 / 音频，进入编辑器并实际试玩 |
| 真实成果离线复跑 | replay / 0 | 使用保存的真实产物重开、编辑、检查和试玩，网络生成调用数为零 |

本地命令以当前 `creator/package.json` 和 `scripts/test.cjs` 为准，在 Creator 目录执行：

```powershell
npm test
npm run build
```

当前 `npm test` 已包含 TypeScript 检查、指定 Node 测试、renderer 测试与 Python unittest；可通过 `CREATOR_TEST_PYTHON` 指向已有可用解释器。`npm run build` 本身不包含 typecheck；若只运行定向测试，必须另跑 `npm run typecheck`。

当前 Node 测试入口只显式列出 `electron/tests/offline.test.cjs`。新增 provider / job-manager 测试文件后，务必更新测试入口，不能假设会自动发现。默认 `npm test` 禁止真实云调用；真实验收用独立显式命令或 IDE 操作，加载持久低额度 profile。

Ren'Py 编译 / lint 与可见窗口试玩都要做，使用现有 SDK 定位和 PreviewManager。lint 不能证明分支、布局与声音正确。真实 UI 自动化使用应用现有测试入口，不通过编辑生成文件、硬改状态或跳过 checkpoint 制造成功。

Windows GUI 预览沿用项目支持的可见桌面启动方式，后台服务窗口隐藏；如果环境只能启动不可见游戏进程，明确记为未完成可见试玩，不把 PID 当成验收证据。

## 11. 交付物与完成标准

执行任务应交付：

1. Seedream 图片与 MiniMax 配音真实适配器及独立设置；其它生成能力的待开发接口。
2. 生成任务、计量、缓存、受管导入、事务绑定和恢复能力。
3. 从简单自然语言生成可编辑、可试玩原生片段的 UI 与工具链路。
4. 确实被执行的零额度测试、真实限额验收入口和离线重放说明。
5. 独立示例工程及其真实产物归档；测试产物保存在被忽略的目录，不自动加入正式游戏或发布包。
6. 一份脱敏验收报告，写明：代码版本、测试命令、自然语言输入、所用模型、每个实际 API 请求次数、计费字符 / usage、产物哈希、两条路线结果、音频试听、保存重开与离线复跑结果。

报告必须分别标识：`mock 已通过`、`真实 API 已通过`、`真实引擎试玩已通过`、`真实成果离线复跑已通过`。若凭据、账户权限、SDK 或真实调用失败导致某项未完成，明确列出原因和剩余工作；不得把“构建通过”写成“功能全部通过”。

最终完成检查：

- [ ] 不需要用户写 JSON 或 RPY，简单自然语言可以生成本计划范围内的片段。
- [ ] 只有 Seedream 与 MiniMax 实际接入媒体生成，文本 AI 使用既有配置。
- [ ] 图片、配音实际入库并出现在真实游戏；没有伪装产物或未声明占位。
- [ ] 素材和剧情仍能在原编辑器继续修改；RPY 是唯一剧情权威源。
- [ ] 真实生成次数与 LLM 请求数在持久额度内，SDK 无隐式收费重试。
- [ ] 同一批真实产物足以完成两条路线试玩、重开和离线复测。
- [ ] 用户密钥未进入仓库、文档、日志、截图或导出游戏。
- [ ] 当前工作区既有修改、正式剧情和其他素材没有被覆盖。
